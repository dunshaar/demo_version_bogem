# Богема — локальное упрощение по ТЗ 5.0

Статичный сайт: главная `index.html`, каталог `repertoire/index.html`.
Сохранены тёмная тема, реальные материалы и обе программы.

## Запуск

Без установки зависимостей и сборки. Локальный сервер поддерживает перемотку MP4:

```sh
python3 "/Users/daniils./Desktop/Богема/Сайт/preview_server.py" 8786
```

Открыть в Google Chrome: http://127.0.0.1:8786/ и http://127.0.0.1:8786/repertoire/.
Сервер слушает только локальный компьютер. Нужен HTTP, а не file://.

## Данные и форма

- `repertoire/data.json` — источник 210 песен группы и 151 песни трио.
- `project-data.mjs` — пять вариантов состава и подтверждённые контакты.
- `preferences-store.mjs` — схема 5: только изменения «Хочу / Не надо»; отсутствие записи означает «Можно». Старые изменения схемы 3 мигрируют с исходными ID, нейтральные отметки и коммерческий выбор удаляются.
- Весь активный каталог виден сразу. Программа из правильной прямой ссылки имеет приоритет перед сохранённой.
- `request-contract.mjs` — строгая схема 2: имя, телефон, необязательная дата, явное вложение с изменениями песен. Старые поля запрещены.
- `forms-config.json` — **локальный деморежим по последнему прямому указанию владельца**. Кнопка показывает «Заявка отправлена», но не отправляет данные. Реальный backend, получатель и доставка будут подключены позже.
- После демонстрации контактные поля и прикрепление сбрасываются; музыкальные пожелания сохраняются отдельно. Контакты посетителя не сохраняются в localStorage/URL.
- Просмотр состава ничего не выбирает и не передаёт в заявку.
- `motion.js / motion.css` — необязательные эффекты и прогресс под шапкой. Контент видим без скрипта; системное уменьшение движения учитывается.

## Проверки и рабочие материалы

ТЗ v5, уточнение владельца, исходные хеши, снимки до/после, проверки и итоговый
отчёт находятся в `../Доработка v5 2026-10-11/`. Тесты формы и плеера — в
`../tests/`. Старые v3/v4 проверки исторические: отменённые поля, поиск и порции
не восстанавливать ради их прохождения.

Полный статический HTML каталога должен совпадать с `data.json` по ID и порядку.
При изменении источника обновлять и HTML, не создавать независимые базы песен.

Серверной интеграции и согласованных юридических документов оператора нет.
Проверки адаптера с подменой ответа не доказывают реальную доставку.
До production нужны реальные документы, серверная валидация, защита от спама,
идемпотентность и проверка доставки разрешённому получателю.
