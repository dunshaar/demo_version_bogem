# Богема — сайт кавер-группы

Публикация: https://dunshaar.github.io/demo_version_bogem/

Статичный сайт: главная и отдельный репертуар. GitHub Pages использует ветку
`main` и корень репозитория; сборка не требуется. Все пути относительные.
Рабочая папка — `Сайт/public`; прежние варианты сохранены отдельно.

## Текущее устройство — 15 октября 2026

- Дизайн перенесён из Framer, сайт работает самостоятельно без Framer runtime
- Шрифты Manrope и Spectral находятся локально, лицензии рядом с файлами
- Desktop hero: Dark Editorial, утверждённое фото, крупный Manrope 300
- Desktop-шапка статичная: Репертуар, Обсудить мероприятие
- Репертуар ведёт на отдельную страницу; обсуждение — к основной форме
- Мобильная шапка закреплена, компактная; меню содержит все шесть разделов
- Промо встроено во второй экран без заголовков; прежние ролик и обложка сохранены
- Промо запускается только по Play; до нажатия показана прежняя статичная обложка
- Прокрутка не останавливает ручное воспроизведение; автоматического повтора нет
- Составы: слева трёхстрочный заголовок и выбор числа музыкантов 01 / 03 / 04 / 05 / 06
- По умолчанию выбран 05; меняется только конкретное описание вокала и инструментов
- Переключатель на нативных radio: клавиатура, touch и работа без JavaScript
- Справа утверждённый снимок 15 октября: оригинальный JPEG без обработки и кадрирования
- Фото не меняется при переключении; названий пакетов и дополнительных CTA нет
- Третий экран сразу после промо: светлый #EEE8DE, «Как звучит ваш вечер»
- 73 утверждённых названия в двух строках: 44 сверху влево, 29 снизу вправо
- Случайный порядок один раз при загрузке; максимум два английских названия подряд,
  включая стык цикла. Кириллические названия разделяют случайные группы по 0–2 английских
- Под строками отдельный ряд с тонким разделителем: иконка паузы слева,
  подчёркнутая ссылка «РЕПЕРТУАР» без стрелки справа
- Составы продолжают светлый фон репертуарного тизера; их стили изолированы в lineups.css
- Непрерывная линейная анимация без пересборки при прокрутке
- Текущие скорости относительно опубликованной v5: верхняя +25%, нижняя +15%:
  49.5 / 43.01 px/s на desktop и 38.25 / 33.235 px/s до 809 px
- Наведение плавно замедляет только свою строку до 40%, уход возвращает 100%
- Ручная пауза имеет приоритет; клавиатурный фокус строки также сохраняет паузу
- Reduced-motion и отсутствие JS: статичные строки с ручной горизонтальной прокруткой
- За пределами экрана и в скрытой вкладке анимации стоят на паузе
- Три live-видео остаются в самостоятельном разделе после репертуара
- Промо загружает видеофайл только после действия посетителя
- Live-видео загружаются после открытия отдельного плеера; серверу нужна поддержка Range

## Финальная настройка лент

База — опубликованная v5 (`6810ec4`), все проценты рассчитаны от неё.
Названия меньше на 6%: 22.56–35.72 px; на 1440 px — 33.84 px вместо 36.
Старый `--type-song` оставлен опорой размеров: ссылка «РЕПЕРТУАР» прежняя.
Межбуквенный интервал сохранён в абсолютных величинах относительно этой базы;
размеры разделителей и промежутки между песнями не менялись.
Между рядами 12.32 px вместо 14 и 7.04 px вместо 8 на мобильном.
Ряды центрированы внутри прежней по высоте области: внешние отступы,
разделитель и следующая секция сохраняют положение с субпиксельной точностью.
Скорости 49.5/43.01 и 38.25/33.235 px/s; длительность цикла пересчитывается
по фактической ширине после загрузки шрифта и при изменении экрана.
Hover меняет playbackRate той же WAAPI-анимации, с плавным переходом 420 ms
между 100% и 40%; без пересоздания анимации, сброса времени или перестановок.
Оба ряда независимы; ручная пауза отменяет переход скорости и сохраняет остановку.
Скрытая вкладка, offscreen и reduced-motion сохраняют прежнее поведение.
Hero, видео, полный репертуар, тексты, фотографии и формы не менялись.

Откат: `before-marquee-final-20261015` → `6810ec4`.

## Промо во втором экране

`promo-video.js` и `promo-video.css` изолированы от плеера live-записей.
Исходный `assets/promo.mp4` не менялся. Обложка задаётся атрибутом `poster`
у видео в `#promo`; запасное изображение при ошибке берётся из того же атрибута.
Автозапуска и управления воспроизведением через viewport больше нет.
Play загружает существующий видеофайл и запускает его с исходным выключенным звуком;
звук включается отдельной кнопкой. После ручного запуска видео продолжает играть
при прокрутке к репертуару и составам. Ручная пауза сохраняется при возврате.
Скрытие вкладки или открытие live-диалога ставит промо на паузу, но закрытие диалога,
возврат во вкладку, fullscreen и pageshow никогда не запускают его автоматически.
Reduced-motion не отменяет явно начатое ручное воспроизведение. Повтор после конца
и повторная загрузка после ошибки — только вручную. Файл и poster не заменены.
Актуальные проверки: `../Marquee video v4 2026-10-15/`.

и не отправляются без подтверждения исключения. Старые ключи сохранены для отката.
Не менять ID существующих песен при будущих обновлениях; статическую разметку
страницы обновлять согласованно с каталогом.

## Формы

На главной обязательны имя и телефон, дата и способ связи необязательны.
В репертуаре только имя, телефон и согласие; пожелания прикрепляются автоматически.
Главная форма полностью независима от песен. Документы подключаются позднее.

`forms-config.json` оставлен в DEMO: подтверждение локальное, данные никуда
не передаются. Контакты и согласие не сохраняются в браузере.
`request-contract.mjs` описывает схему 3 для будущего обработчика; текущие
пожелания используют `program: all` и ID `all-song-*`. Перед подключением
обработчик должен поддерживать именно этот каталог и контракт. Секретов в сайте нет.
